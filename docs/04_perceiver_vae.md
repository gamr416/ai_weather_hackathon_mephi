# Perceiver IO и Perceiver-VAE

## Perceiver IO — простыми словами

Обычный Transformer плохо масштабируется на огромные входы (вся карта погоды = миллионы точек).

**Perceiver** делает иначе:

1. Есть небольшой набор **latent-токенов** (фиксированный размер).
2. Они через **cross-attention** «смотрят» на большой вход (Encode).
3. Тяжёлая обработка идёт уже в маленьком latent.
4. Для выхода: **query-токены** через cross-attention достают нужные значения (Decode).

Итог: сложность линейна по размеру входа/выхода; формат входа и выхода может быть разным.

Статья: [Perceiver IO (ICML 2022)](https://arxiv.org/abs/2107.14795).

```
Input array  ──cross-attn──►  Latent N  ──self-attn──►  Latent'
                                      │
Output queries ──cross-attn───────────┘──► Output array
```

## VAE — зачем поверх Perceiver

**VAE (Variational Autoencoder)** учит не просто «сжать и восстановить», а **вероятностное latent**:

- энкодер выдаёт распределение (обычно среднее и дисперсию);
- из него сэмплируем latent-код;
- декодер восстанавливает поле;
- loss = **искажение** (насколько плохо восстановили) + **rate** (насколько «дорогой»/большой код).

Это и есть **rate–distortion** цель: баланс «качество ↔ сжатие».

Ближайший погодный аналог и **baseline хакатона**: **VAEformer → CRA5**.  
В ТЗ цель скромнее по битрейту (**×32–×64** по bitstream), но с формальной **non-inferiority** к VAEformer и явным исследованием **data efficiency** (\(N\) уникальных кадров). См. [task.md](task.md).

## Perceiver-VAE (идея проекта)

Склеиваем:

| Кусок | Откуда | Роль |
|-------|--------|------|
| Perceiver IO encode/decode | Aurora / Perceiver | Универсальные входы/выходы, query-driven decode |
| VAE + rate–distortion | CRA5 / классический VAE | Настоящее сжатие и latent для downstream |
| Дообучение на новые переменные | Aurora-стиль (новые MLP / heads) | Кодек не ломается при новых полях |

### Предполагаемые применения

1. **Кодек** — сжать реанализ / спутниковые поля.
2. **Forecast на latent** — прогнозировать в скрытом пространстве, декодировать только в конце.
3. **Произвольная сетка на выходе** — декодируем тем, что спросим через queries (переменная, уровень, lat/lon).

## Что обычно нужно закодировать во вход

Для каждого токена/точки полезны признаки:

- **lat, lon** (лучше со сферическими / Fourier-фичами);
- **level** (давление);
- **variable** (тип поля);
- **time**;
- **mask** (дыры, суша/море, missing).

## Практические трюки обучения (из описания темы)

- Rate–distortion objective.
- Physics-aware и spectral regularizers (не ломать спектр и физ. ограничения).
- Curriculum: сначала грубо, потом тоньше.
- Mixed precision + activation checkpointing (экономия памяти).
